## 1. J5 — 之前确实没锁上，两个原因

**分支覆盖 bug**：

```python
if mode == "srs":   ...装 SrsIK...
if mode == "opt":   ...装 AR5OptIK（锁 j5 的代码在这里）...
else:               env.arm._kinematics = AR5IK(...)   # ← else 挂在 opt 上
```

`--ik srs` 时 SrsIK 装好后立刻被 `else` **覆盖成 DLS**，而横幅照常打印 srs。锁 j5 的代码只在 opt 分支，一并失效。改成互斥哨兵了。

**第二个原因**：闭式解的 j5 是腕部 ZYZ 分解**唯一确定**的，没法自由固定（固定了就少一个姿态自由度，闭式无解）。实测 `--ik srs --lock-j5 0` 时 j5 照样走了 **21.9°**。现在这两个参数会明确互斥并提示。

而且我以前**没有任何测试覆盖 IK 注入**——MockArm 没有 `_kinematics`，那段代码从来没在 mock 里跑过。现在加了开机自检，直接问求解器要个解并验证：

```

[自检] j5 锁定验证: 解出 j5=+0.000°，距设定值 0.0000°  ✓ 锁住了
```

用 `--ik opt --lock-j5 0.0`（不要配 srs）。

## 3. 是的，是笛卡尔 delta 增量

## 修法

加了 `ToolFrameKinematics`，把 fk / jacobian / ik 整体搬到工具中心。关键是**必须成对换**：`get_ee_pose` 也一起包，少一个就是新的不一致。实测整条链偏差 8.85e-12，闭环伺服到达误差 0.0064mm。

默认开启（`--tcp-z > 0` 时），要对比旧行为用 `--flange-frame`。

过程中我自己的两个测试都写错过，都被数据打脸后才发现：先是绕末端**自身 Z 轴**转——而工具偏置正好沿 Z，杠杆为零，什么都测不出来；还有 `AR5OptIK._fk_jac` 抄了 `base._chain()` 的近路**绕过包装类**，导致工具系恒偏 147.7mm（正是偏置本身）。

**两个要说清楚的：**

1. 工作空间盒 `workspace_min/max`（前后 ±180mm、上下 ±170mm）原来是按**法兰**定的，现在约束的是工具，等于整体前移了 150mm。可能需要重新标定这个盒子。

2. `--tcp-z 0.150` 这个数本身还是我按 211.5mm 的 70% **猜的**。现在它直接决定旋转中心，猜错多少就偏多少。**法兰到你实际捏取点的距离，量一下给我**——这条现在比以前重要得多。
