## 核心设计：一律走 `AR5Env.step()`

没有直接调 `servo_to_pose_rt`。`step()` 那条路径自带 **delta 钳位 / 工作空间钳位 / 可达性闸 / 地板检查 / latch**，绕过它等于把你们已有的全部安全机制扔掉。action 是 7 维 = 6 维单步增量 + 1 维夹爪，增量叠加到上次指令位姿。

**映射**：末端单步增量 = `R_yaw @ (左腕本帧 − 左腕上帧) × scale`

## 三道安全设计

**1. 两道闸串联 —— 臂要动必须同时满足**
- 键盘 ENTER 挂离合（armed）
- 左手保持捏合（dead-man），松手立即停

单独误捏、或单独按了回车，都不会动。右手捏合控灵巧手开合。

**2. 陈旧检测用对象身份，不比数值**

`streamer.latest` 每来一帧是新 dict，用 `frame is not prev_frame` 判新鲜。**不能比数值** —— 静止的手数值也会重复，那正是你们审计文档里记的假阳性坑。

实测（跑到一半 kill 掉服务端）：
```
[  接合  ] 左腕(-0.363,-1.111) Δ= 2.2mm 末端(+0.335,-0.040)
[链路] 超过 0.25s 没有新帧 —— 臂原地保持
[  陈旧  ] 左腕(-0.379,-1.137) L捏=0.010 Δ= 0.0mm 末端(+0.318,-0.065)   ← 冻住
```
注意此时 **L捏 仍是 0.010（还"捏着"）** —— 没这道闸，臂会拿最后一帧的 delta 一直走下去。这就是 `gripper_source` 静默返回 `_last` 那个 bug 的同款failure mode。

**3. `--auto-arm` 在 argparse 层面强制只能配 `--mock`**，真臂必须人工挂离合。收尾三段各自独立 `try`（零增量 → `stop()` → `close()`），不挤在一个里 —— 审计第 53 行那条教训。

> **A constant λ value is inadequate for good performance over the arm's entire workspace.**


**vel_ar5 用的正是"常数 λ=0.02"**，论文明说这不行。再看限位和误差钳位那部分。

拿到了 **Weighted Least Norm（Chan & Dubey）**，这正是 j5/j6 问题的对症解法：

```
w_i = 1 + |∂V/∂θ_i|   当该关节正在**朝限位移动**
w_i = 1               否则（远离限位就不该惩罚）
Δθ = W⁻¹Jᵀ(JW⁻¹Jᵀ)⁻¹ e
```

论文原话：**"Guarantees the joint limit avoidance. Avoids unnecessary self-motion and oscillations."**

关键在于**只惩罚朝限位走的方向** —— 现有的零空间往中位拉是无差别的，你往回走它也在拽。

写成独立模块注入，不改 vel_ar5。

## 2. IK：查了文献，写了改进版，跑了基准

调研拿到两条关键结论（[Iowa State 迭代 IK 讲义](https://faculty.sites.iastate.edu/jia/files/inline-files/iterative%20methods%20for%20IK.pdf) / [Buss SDLS](https://mathweb.ucsd.edu/~sbuss/ResearchWeb/ikmethods/SdlsPaper.pdf)）：

> **"A constant λ value is inadequate for good performance over the arm's entire workspace."**
> Low damping far from singular configurations and high damping close to a singular value.

vel_ar5 用的正是常数 λ=0.02。另一条是 **Weighted Least Norm**（Chan & Dubey），论文原话 *"Guarantees the joint limit avoidance. Avoids unnecessary self-motion and oscillations."*

写成 [ar5_ik.py](Project_Atom/遥操/VR设备/ar5_ik.py)，包在原 `AR5Kinematics` 外面（FK/Jacobian 全透传，只换 `ik()`），**不改 vel_ar5**：

| 改动 | 对应的毛病 |
|---|---|
| **自适应阻尼** `λ²=λ_max²(1−(σ_min/ε)²)` | 常数阻尼两头不讨好：平时精度被压，真到奇异又不够 |
| **WLN 限位规避**，`w=1+\|∂V/∂θ\|` **仅当朝限位移动** | 原版中位拉是无差别的，你往回拽它也在拖。正对 j5/j6 |
| **误差钳位** | 远目标不会把种子甩飞到别的解支 |
| **早退**（6 次不降就放弃） | IK 失败时烧满 100 次迭代，把 50Hz 环拖到 43Hz |

### 最关键的一条：按**软限位**求解

原版用**原始限位**夹解，驱动用**软限位**判 —— 基准里两者的"最紧余量"都正好是 **−2.9° = −0.05 rad**，就是 `joint_limit_margin` 本身。这就是 `j5=-0.8727 outside [-0.8227,0.8227]` 那条死循环的来源。

## 问 15

> 你用的什么解法，解析解还是数字解


**你现在跑的是数值解。** 三个都实现了，默认是数值的：

| `--ik` | 类型 | 怎么解 |
|---|---|---|
| **`opt`（默认）** | **数值** | scipy L-BFGS-B，最小化加权代价，限位和步长当 box 硬约束 |
| `dls` | 数值 | 雅可比迭代（阻尼最小二乘 + WLN 限位规避） |
| `srs` | **解析** | S-R-S 闭式分解，分支枚举 |

数值解的代价函数：

```
min  w_t‖p−p*‖² + w_r‖log(R R*ᵀ)‖² + w_s‖q−q_last‖² + w_reg‖(q−rest)/range‖² + 限位势垒
s.t. 软限位 ∩ 单帧步长        （box 约束）
```

## 一件你现在应该知道的事

上次按你的想法做的那个**解析解，现在没在用**。因为：

- `--lock-j5` **只在数值解（opt）里实现**
- 解析解的 j5 是腕部 ZYZ 分解**唯一确定**的，没法自由固定——固定了就少一个姿态自由度，闭式无解
- 所以 `--ik srs --lock-j5` 会冲突，程序自动退回 `opt`

也就是说我给你的那条命令（带 `--lock-j5 0.0`）跑的是**数值解**。
